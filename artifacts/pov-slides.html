🧑‍💻

☁️
Azure infrastructure setup, model selection, or service configuration — these follow from the brief

The AI-assisted coding process itself — the engineer runs and reviews all generated code
📝
Inventing requirements during implementation — new requirements go back through the brief, not into ad-hoc messages
🔎
Replacing engineering judgment — trust the engineer on technical decisions; stay available to clarify the business intent
The key split: the manager converts ambiguity into clarity. The engineer converts clarity into a working demo. If the brief is unclear, the prototype will be wrong — no amount of coding fixes that.

Why Prototypes Fail
Manager Guide
A prototype should deliver clarity and a path forward — these are the things that prevent it
Business Case
Why this matters, what problem it solves, why it is worth doing. If you can't state it in 1–2 sentences — you're not ready.
"Field engineers waste hours searching for relevant safety incidents — AI can surface them instantly."
Demo Scenario
Not why — that is the business case. This is what exactly we show: the steps, the data, the expected result. Define before coding.
BLOCKER
The Data
Where does it live? Who owns it? Data access is the #1 real-world blocker. Resolve early.
The Environment
Default: VIAcode-controlled CSP subscription. Deviate only by explicit request. Which services? Who grants access?
Success Criteria
Measurable and agreed in advance.
"Answers well" ≠ criterion.
"7/10 rated correct by expert" = criterion.
Demo Audience
Architect vs. business sponsor read the same demo very differently. Know who's in the room.
Scope Boundary
What is explicitly OUT? Protection against scope creep — as important as what's in.
This is why our process exists
When these are left unclear, the engineer builds something — just not what the customer needed. Our process catches this before coding starts.
6 Recurring Patterns
Manager Guide
No single code template covers all of these — knowing the pattern matters
📄
Intelligent Search / Q&A Over Documents
Natural language queries over a corpus of documents: manuals, policies, reports, contracts. Retrieves relevant content and generates a response. Common in industries with large documentation libraries.
Azure AI Search Azure OpenAI
📊
Data Analysis & Insight Generation
Automated summaries, anomaly detection, or plain-language reporting from structured/semi-structured data. Surfaces insights that were previously buried in spreadsheets or BI tools.
Azure OpenAI PostgreSQL pgvector trigram
📄
OCR / Document Extraction
Extracting structured data from scanned or unstructured documents — medical records, invoices, forms, contracts. Common when source data is image-based or handwritten. Often paired with Q&A over the extracted content.
Azure Document Intelligence Azure OpenAI
⚙️
Process Automation / Workflow Assistant
Repetitive knowledge work — drafting documents, classifying requests, routing tickets, extracting data from forms. The prototype demonstrates one step of the process working end-to-end.
Azure OpenAI AKS
💬
Conversational Interface Over Internal Data
Chat-based interaction with internal knowledge or systems. Differs from Pattern 1 in its emphasis on conversation flow and multi-turn interaction, not just single-query retrieval.
Azure OpenAI AI Search Custom layer (AKS)
🤖
Multi-Step / Agent-Based Workflow
Sequence of decisions, tool calls, and sub-tasks — look up, reason, act, verify. Under the hood: Claude Code CLI with a custom orchestration layer on top. More complex to scope; define the loop carefully before building.
Claude Code CLI Custom orchestration AKS
⚠️ No single code template covers all 6 patterns well. The value is knowing which pattern applies — and our preferred stack: AKS · PostgreSQL (pgvector + trigram) · Azure OpenAI · Azure Document Intelligence.

Definition of Success
The customer is willing to consider project continuation.
They want to discuss the next stage — MVP, timeline, investment.
✔ Demo works end-to-end, runs on real data
✔ Customer champion can show it internally to justify further investment
✔ Customer can estimate ROI: value vs. effort and cost
NOT a failure if:
• Doesn’t handle every edge case or isn’t production-ready
• Continuation didn’t happen — budget, priorities, or economics may have changed
• Customer learned what they need — even if the answer was “not this”

Starting Implementation & Avoiding Mistakes
Manager Guide
What the handoff brief must contain — and what commonly goes wrong
The Handoff Brief
When ready, hand the brief to the engineer in writing. It must include:
1
The business case (1–2 sentences)
2
The demo scenario (step-by-step walkthrough of what will be shown)
3
Data description and access method
4
Target environment and available services
5
Measurable success criteria agreed in advance
6
Scope exclusions / non-goals — what is explicitly out
💡 A good brief takes an hour or two to produce. It saves days of rework.
Common Anti-Patterns
❌
Starting before the data question is answered — prototypes built on placeholder data often need to be substantially rebuilt when real data arrives
❌
No success criteria before building — without “done,” every demo becomes a negotiation
❌
Asking the engineer to figure out requirements as they go — produces an impressive thing that answers the wrong question
❌
Treating the prototype as the start of a production system — leads to technical debt and broken expectations
❌
Overclaiming what the prototype proves — a prototype on curated data does not prove production viability
❌
Skipping manager review before the demo — surprises at demo time are avoidable

How to direct it effectively
Be specific about what's wrong
✗ "it doesn't work"
✓ "POST /search returns 403 — the header key name is wrong, it should be api-key not Authorization"
Fix and extend, don't throw away
Ask Claude to fix the specific issue in existing code. Regenerating from scratch loses context and creates drift.
Name the scope boundary explicitly
✓ "Only touch the search handler. Don't change the UI or data model."
Keep secrets out of the prompt
Tell Claude to use env vars or Key Vault references. Never paste real API keys into the conversation.
