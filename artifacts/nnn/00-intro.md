# Rapid Prototyping Documentation Set — Introductory Note

## Why This Documentation Exists

This set of documents was created to replace an informal narrative that had developed around our rapid POV and prototype capability. Over time, that narrative had drifted toward describing our approach as a kind of proprietary "AI Core" platform — a pre-built library of agents and building blocks that gives us special leverage.

That framing was never entirely accurate, and it is now actively misleading. Modern AI-assisted coding tools have changed the landscape. Many things that once required carefully maintained code libraries can now be generated on demand. Claiming competitive advantage based on having "special agents" or "more pre-built blocks" is no longer a credible position — and it sets the wrong expectations with customers and internal teams.

The actual value we deliver is different:

- We know how to translate vague customer intent into something implementable.
- We follow a repeatable process that avoids common waste.
- We can use AI-assisted coding effectively and responsibly.
- We make practical choices in Microsoft/Azure-centric environments.
- We can go from a business question to a working demonstration quickly.

## How to Use These Documents

| Document | Audience | Purpose |
|---|---|---|
| `01-manager-guide.md` | Manager, coordinator, pre-sales, solution lead | How to initiate, prepare, and hand off a rapid POV engagement |
| `02-implementation-instruction.md` | Implementer (developer or technical person executing the build) | How to start from a brief and execute using AI-assisted coding |

**The manager or coordinator reads `01-manager-guide.md` and does the preparation work.** Once a clear brief exists, **the implementer reads `02-implementation-instruction.md` and executes against it.**

Neither document is optional. Most prototype failures trace back to one of the two roles being skipped or rushed.
